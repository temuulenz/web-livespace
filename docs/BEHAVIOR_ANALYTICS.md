# Phase 11E/F analytics contracts

Approved acceptance: PHASE11_ACCEPTANCE.md. Both Node and Cloudflare use existing sessions/RBAC and the same validators/reports. Collection is disabled unless LS_ANALYTICS_ENABLED=1; no UI handlers were changed. Domain metric sources remain authoritative; browser events are explicitly unverified observations, never physical visits, purchases, revenue, conversions or trained forecasts.

## Collection

POST `/api/v1/analytics/session` with `{}` initializes the session-only HttpOnly SameSite=Lax `ls_analytics` cookie (Secure under HTTPS). Response `{ready:true}`. Initialize before anonymous intake so a retried first batch retains its pseudonym. Authenticated and anonymous visitors share this same analytics-session mechanism; account/session credentials are never copied into analytics. The cookie is scoped to `/api/v1/analytics`. There is no persistent visitor ID, precise location, fingerprint or raw-IP analytics column. Ephemeral security rate limits reuse IP windows without recording them in event/aggregate storage.

POST `/api/v1/analytics/events`, JSON <=16 KiB:

```json
{"schemaVersion":2,"cafeId":"CAFE_ID","events":[{"id":"random-event-0001","type":"product_view","productId":"PRODUCT_ID"}]}
```

1–32 events; event IDs 8–64 ASCII letters/digits/underscore/hyphen. Types: cafe_view, cafe_search, filter_apply, menu_view, product_view, favorite_add, favorite_remove, promotion_view, promotion_click, directions_click, review_submit, out_of_stock_view. Only `id,type,productId,promotionId,filter` are permitted. Product views require productId; promotion views/clicks require promotionId. IDs must belong to the cafe; products/category must be publicly published. Filter values are noise/wifi/availability/goal/district on filter_apply only. Search terms, arbitrary metadata, client timestamps, location and identities are rejected. A search event is cafe-scoped; aggregate discovery behavior is reported by the relevant cafe rather than retaining a global query history.

Server supplies timestamp/hour and a SHA-256 session pseudonym scoped independently to each cafe. Acceptance is durable before HTTP 202 `{accepted,duplicates,serverTimestamp}`. Identical IDs/payload/session within receipt retention deduplicate; changed content/session conflicts (409). Do not reuse IDs or retry past the documented dedup window (default two days). Batch conflicts/limits roll back the entire intake. Configurable defaults: 20 batches/IP/minute, 100 new events/session/local day, 1000/cafe/local day. Limits 429; disabled 404; paused 503; schema/reference 422. Existing JSON/origin/body/storage error envelopes apply. V1 events remain compatible with the original minimal validator and hourly counters; v1 lacks session/dimension attribution and is not silently mixed into v2 unique-session/product reports.

The existing per-cafe AnalyticsAggregator DO persists receipts, counters and session/dimension memberships; it flushes absolute monotonic revisions to D1, not a raw event row for every browser action. Ambiguous flushes safely retry. Node uses the same collector in durable SQLite files under LS_DATA_DIR/analytics, a 16-handle cache and round-robin flush recovery. No D1 billing is inferred from Node work. Summary members contain only per-cafe pseudonyms/day/dimension, are private, and support exact cohort suppression/unique sessions within retention. They contain no individual event timestamps/history in D1. Default 90-day bounded aggregate/membership retention and two-day receipt retention; accepted unflushed counters are never discarded by retention. Cleanup is incremental; a backlog can temporarily retain older records. Disabled collection preserves pending data and stops optional collection/flush work.

## Owner/admin reports

GET `/api/v1/owner/cafes/{cafe}/analytics` and `.csv`; equivalent `/api/v1/admin/cafes/{cafe}/analytics[.csv]`. Owner requires actual current cafe ownership; admin may inspect a cafe or use `/api/v1/admin/analytics[.csv]` for platform aggregates. Public access denied. No researcher role or raw visitor export.

Query: `since=YYYY-MM-DD`, `until=YYYY-MM-DD` (exclusive), `granularity=day|week|month`, `compare=true|false`, `source=real|simulated`, `limit=1..100`, `offset=0..10000`. Dates are Asia/Ulaanbaatar midnight boundaries; storage remains UTC. Default last seven local calendar days including today, <=31 days configurable to 93, no future period beyond tomorrow. Weeks start Monday; months start on day one. Comparison uses the immediately preceding equal-duration local-date interval, including nonaligned week/month edge buckets. Each bucket is clipped to the requested interval. Legacy Cloudflare hourly/ISO-time requests remain on the existing v1 analytics interface.

Response `{cafe_id,scope,since,until,granularity,source,current,previous}`. `current`/`previous` include:

- `behavior`: bucket/type/product/promotion/count/session aggregates, paginated. Cohorts with fewer than five distinct pseudonymous sessions (configurable minimum 3) are omitted entirely, including their product/promotion keys; `suppressed_cohorts` and `behavior_status` explain suppression. Owners never receive pseudonyms, receipt IDs or event rows.
- `unique_sessions`: distinct cafe-scoped sessions or null below cohort threshold. Platform unique sessions are null because cafe pseudonyms deliberately cannot be linked across tenants.
- `cafe_profile_views`, `menu_views`, `popular_menu_items`, promotion impressions/clicks: named projections of the returned safe behavior page. Popularity is descending event count within that page (`popular_items_scope=returned_page_only`); use pagination to inspect other items. CTR is clicks/impressions only when all necessary cells are unsuppressed and the page is complete; otherwise null. These are browser-event metrics, not sales conversion.
- `current_favorites`: current authoritative favorite rows, a snapshot rather than historical additions. `review_count`/`average_rating`: currently visible nondeleted reviews created in the interval, not every review ever submitted. Empty mean is null.
- Inventory: current status distribution. Historical availability fractions are explicitly null/unavailable because no complete status-duration history exists. No reservations/orders are inferred.
- Sensors: one latest reporting device per cafe/source, never summed overlapping cameras; aggregate occupancy/peak, calibrated SPL, separate uncalibrated dBFS, Wi-Fi quality/down/up/latency, local peak hours and distinct cadence-slot coverage. Invalid, stale-at-arrival and simulated observations are excluded from real results. Sparse coverage reports insufficient; empty reports unavailable. Real/simulated output is explicitly source-separated. Current registered online/total counts are available; historical connection uptime is null without an incident-duration dataset. Delayed historical uploads never make stale readings eligible.

Snapshots cache for 30 seconds in a 128-entry runtime cache; authorization runs before cache hits. Reports can lag durable intake until bounded flushes finish, then up to cache TTL. Owner reads request one bounded flush; repeated flushes/alarms drain larger queues. Platform reads never invoke unbounded fan-out across collector objects. Query ranges, response sizes, result/cohort limits and SQL tenant/time indexes bound work. CSV exports only the same safe returned aggregate page(s), quoted and formula-neutralized, never member hashes. CSV starts with period,bucket,event_type,product_id,promotion_id,count,status. Unsupported metrics stay null with explicit semantics.

Testing and metadata: phase11-analytics.test.mjs, phase11-resources.test.mjs, local Cloudflare integrated check, PHASE11_EH_D1_MEASUREMENTS.json. No provider CPU, global capacity or physical sensor calibration claim.
