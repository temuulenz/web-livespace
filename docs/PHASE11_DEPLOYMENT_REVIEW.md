## Security and data review

Authentication reuses ls_session, token hashes, enabled-user/auth-version lookup and Super Admin policy. No new owner credential or recipient API was introduced. Same-origin writes use Origin checks and SameSite=Lax/HttpOnly cookies; Node production must set secure cookies and trust forwarded headers only behind a restricted proxy. Origin-less nonbrowser requests are allowed by the existing policy; this is not a replacement for authenticated authority. Logout/password/role revocation and private-room reauthorization have regression coverage. New authority fences close demonstrated mutation races; they use existing 409 version_conflict behavior on in-flight authority loss, with no new schema or credentials.

Tenant references use prepared statements, authoritative cafe ownership and composite FKs. Admin oversight of analytics/resources intentionally differs from A–D owner mutations, where admin still must actually own the cafe. Review authors cannot moderate; owners cannot hide criticism. Recipient IDs/actors/ownership are server derived. Public responses omit account IDs/emails, moderation/report details, diagnostics, receipt/session hashes and secrets. Private responses are no-store; private media must reauthorize even for 304. Unknown body fields, booleans, safe integers, enum/time ranges, request sizes, pages and batch sizes are checked. Report query parsing tolerates unrelated query keys; do not assume a body whitelist also rejects every query key.

CSV parsing is bounded before meaningful work; exact header, quotes/CRLF/field count/numeric validation and tenant relationships are enforced. Confirmation is an explicit round trip, bound to identical bytes/cafe/user; all rows are drafts in one transaction. Imported names/descriptions are plain text, not executable formulas. Aggregate exports quote/escape and neutralize leading spreadsheet formula characters; only the returned safe behavior page is exported, not raw members or all metrics automatically. Render all stored strings as text in the frontend.

Media accepts canonical JPEG/PNG/WebP data URLs with actual header/type/size/dimension checks, no SVG/HTML/remote URL upload or caller path. The parser is structural, not a pixel decoder/malware/metadata scrubber; EXIF sanitization is not implemented. Raster MIME/nosniff/conservative cache policy reduce executable-content exposure. Node tenant paths/R2 keys are generated. Pending storage reserves quota, late writers are fenced by reconciliation tombstones, referenced media is never deleted on ambiguous failures. The new authority check also precedes reservation/storage and runs before attach/detach commits. Storage-only failures can retain pending objects for reviewed cleanup.

No blanket assertion of “all endpoints distributed-rate-limited” is supported. Admission is application-level, with explicit platform-unavailable measurements. Existing user review creation/deletion can accumulate soft-deleted rows/audits; permanent correctness receipts deliberately outlive visible content. Capacity must account for these rather than assuming aggregate retention bounds the entire database.

## Database and compatibility

Node PRAGMA foreign_keys=ON, busy_timeout=3000, WAL for files, synchronous=FULL; ordered transactions advance user_version only after successful migration. D1 0009/0010/0011/0012/0013/0014/0015/0016 correspond to Node 5–12; earlier D1 numbering differs because of Cloudflare-specific migrations. No migration was edited or down-migrated in this review.

Menu tenant/global reservation CHECKs and insert/delete counters are atomic; archived/inactive/pending records count toward caps. Upgrade 0010 seeds counters and safely fails on over-cap legacy data, so “additive” does not mean “cannot block startup.” Inventory composite relationships/source exclusivity/nonnegative state and immutable movements/receipt identities are enforced. Reviews have one active author/cafe partial unique index, generated rating and incremental visible aggregates. Promotions preserve tenant target references/capacity. Analytics has tenant/time/member indexes; notification inbox/due/unread indexes and recipient/event uniqueness support private polling/admission. Not every enum/counter has a database CHECK (for example outbox categories/resource levels); service-controlled writes remain part of the integrity boundary.

A disposable frozen-v1 upgrade and backup restore rehearsal in this review yielded user_version 1→12, integrity_check=ok and zero foreign_key_check rows both after migration and after restoring the migrated backup. Unit tests additionally compare shared/D1 schema text and exercise failed transactions/concurrent quotas. Local workerd applies the actual ordered D1 migration files. This does not rehearse the unknown production data volume/over-cap conditions or provide a production backup.

Durable sensor ACK remains after COMMIT; retries retain stable device/message identity through history retention. Analytics instead uses a documented finite receipt horizon. Never delete sensor/inventory/notification dedup identities during recovery. Old API/static fallback and original fidelity fixtures passed checks; additive price/inventory/report fields require the integration semantics in the handoff.
