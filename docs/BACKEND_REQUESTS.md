# Backend-д хүсэх өөрчлөлтүүд

Эзэмшигчийн самбар болон хамтрах маягтын UX-ийн ажлыг зөвхөн frontend дээр хийсэн. Сервер,
мэдээллийн сан, API-д ямар ч өөрчлөлт ороогүй. Доорх зүйлсийг backend талаас хийвэл маягт
богиносож, эзэмшигчийн самбар илүү хялбар болно. Эхний 4 нь хамгийн чухал.

## 1. Хамтрах маягт (`POST /api/v1/applications`)

Одоо `server/routes/partner.mjs` болон `cloudflare/partner.mjs` хоёулаа дараах талбаруудыг заавал
шаарддаг: `cafe_name`, `contact_name`, `phone`, `email`, `district`, `category`, `address`, `hours`,
`description`, мөн 3–4 зураг. Тиймээс frontend эдгээр талбарыг бүгдийг нь хэвээр асууж байна.
Шалгалтыг тойрохын тулд хуурамч утга автоматаар бөглөхгүй.

| # | Хүсэлт | Яагаад |
|---|---|---|
| 1 | **`email` заавал биш болгох.** Утасны дугаар хангалттай. Ирсэн бол формат нь шалгагдсан хэвээр байна. | Ихэнх эзэмшигч утсаар холбогддог; и-мэйл нь маягтыг удаашруулна. `cafes.email` багана аль хэдийн `NOT NULL DEFAULT ''` тул схем өөрчлөх шаардлагагүй. |
| 2 | **`description` заавал биш болгох.** | Эзэмшигч тайлбарыг дараа нь самбараас (`PATCH /owner/cafes/:id` → `description`) нэмж чадна. |
| 3 | **Зургийг 0–4 болгох** (одоо 3–4). Мөн дараа нь нэмэх зам гаргах: жишээ нь `POST /owner/cafes/:id/application-photos`. | Утсаар маягт бөглөж байхад 3 зураг заавал авах нь саад болдог. Зураглалын баг зургийг дараа нь хүсэж болно. |
| 4 | **`category` ирээгүй үед `'Кафе'`-г анхдагч болгох.** | Одоогоор зөвхөн кафетай ажиллаж байна. Frontend «Кафе»-г урьдчилан сонгосон боловч сервер талд мөн анхдагч утга байвал аюулгүй. |

Эдгээр өөрчлөгдвөл frontend-д хийх зүйл: `js/features/partner/partner-form.js`-ийн `required` болон
`MIN_PHOTOS`-ийг тааруулах. Тест: `tests/browser.mjs` («partner form validation…»), `tests/e2e.mjs`.

## 2. Эзэмшигчийн самбар (`GET /api/v1/owner/cafes`)

| # | Хүсэлт | Яагаад |
|---|---|---|
| 5 | Эзэмшигч хаяг, дүүргээ засах боломж: `PATCH /owner/cafes/:id` нь `address`, `district`-г хүлээж авах. | Хаяг хоосон үед «Хаяг оруулаагүй — нэмэх» гэж засах газар руу чиглүүлэх боломжгүй байгаа тул одоогоор зүгээр нууж байна. |
| 6 | Төхөөрөмж бүрт `kind`-аас гадна энгийн нэр (жишээ нь «Лангууны утас») хадгалах. Одоо `label` хоосон үед frontend «Утас» гэж харуулж байна. | Эзэмшигчид ойлгомжтой. |
| 7 | Цагийн тайлангийн тусгай endpoint (`/owner/cafes/:id/report?range=today|yesterday|week`): цаг бүрийн дундаж хүн, хамгийн ачаалалтай цаг. | Одоо frontend нь `sensor-history?interval=60&since&until`-ийг ашиглан өөрөө тооцдог. Энэ нь ажилладаг ч 7 хоногийн хүсэлт том болох магадлалтай. |

## 3. Тэмдэглэл

- «Ирэх зочид», «захиалга» нь одоогоор `js/services/customer-adapter.js`-ийн **mock** адаптераас
  ирдэг. Тиймээс эзэмшигчийн дээрх картууд дээр **ДЕМО** гэж тэмдэглэсэн. Бодит API
  (`docs/PHASE11_API_CONTRACT.md`) холбогдсоны дараа шошго өөрөө алга болно.
- Хөдөлгөөнт зураглалын өрөөний тохиргоо (орц, цонх, тайрсан булан, VIP өрөө, шинэ загвар) нь
  засагчид урьдчилан харагддаг. Гэхдээ `sanitizeLayout` (`server/services/visualization.mjs`) эдгээр
  түлхүүрийг хадгалахгүй. Хадгалуулахын тулд `overrides.door`, `overrides.windows`, `overrides.cuts`,
  `overrides.vip` болон `layout.look`-ийг зөвшөөрөх шаардлагатай. Утгуудыг шалгах дүрэм:
  хана дээр байх, шал дотор байх, өнгө `#rrggbb` хэлбэртэй байх.

## 4. Хөдөлгөөнт зураглал: чөлөөт объект, лангууны хэмжээ, кафены дизайн

Frontend одоо зураглалд чөлөөт объект (`layout.items`), захиалгын лангууны хэмжээ ба эргэлт
(`overrides.counter.w`, `.h`, `.rot`) болон кафе тус бүрийн дизайн файлыг (`js/simulation/designs/`)
дэмждэг. Backend-д хүрээгүй тул `sanitizeLayout` эдгээрийг хадгалахгүй. Одоогоор эдгээр нь дизайн
файлаар (засагчийн «Дизайн файл (JSON)») хадгалагдана. Админ сайтаас шууд хадгалдаг болгохын тулд:

- `layout.items`-ийг зөвшөөрөх. Шалгах дүрэм нь `js/simulation/catalog.js`-ийн `sanitizeItems`-тэй
  ижил: зөвхөн `CATALOG`-д байгаа `type`, `x` 0–800, `y` 0–520, `w`/`h` төрлийн min–max дотор,
  `rot` −180–180 бүхэл тоо, төрлийн `props` (int хязгаартай, select сонголтоос, text ≤ 30 тэмдэгт,
  өнгө `#rrggbb`), нийт ≤ 300 объект. Бусад түлхүүрийг хаях.
- `overrides.counter`-т `w`, `h` (100–360) ба `rot` (−180–180)-ийг зөвшөөрөх.
- Хэрэв серверт хадгалах бол дээрх 3-р хэсгийн `door`, `windows`, `cuts`, `vip`, `look`-ийг хамт зөвшөөрөх.
- Node ба Cloudflare (`cloudflare/worker.mjs`) хоёулаа ижил `sanitizeLayout` ашигладаг тул нэг
  өөрчлөлт хоёуланд нь хүрнэ. Хуучин `{ preset, overrides }` өгөгдөл хэвээр ажиллах ёстой.

## 5. Шинэ нүүр хуудас (Design C): API-д байхгүй өгөгдөл

Нүүр хуудсыг зөвхөн frontend дээр хийсэн. Доорх өгөгдөл API-д байхгүй тул хуурамчаар бөглөөгүй:
мэдээлэлгүй хэсэг нуугдана.

| # | Хүсэлт | Одоогийн байдал |
|---|---|---|
| 8 | **Кафены нийтийн зураг:** `GET /cafes` бичлэг бүрт `photos: [{ url, alt }]` (эхнийх нь нүүр зураг), эзэмшигч/админ оруулж, дарааллаа өөрчилнө. Хаяг нь `https://` эсвэл өөрийн сайтын `/…` байна. | Frontend үүнийг шууд дэмждэг (`js/features/home/cafe-photos.js`). Түүнийг хүртэл зөвхөн Sunny Day-ийн кафены өгсөн 4 зураг `js/features/home/photos/`-д, дизайн файлынх нь нэрээр таарна. Зураггүй кафе «Онцлох кафе» слайдад орохгүй; картан дээр «Жишээ зураг» шошготой зураглал гарна. |
| 9 | **Онцлох байрлал (төлбөртэй):** `featured: { until, label }` эсвэл тусдаа `GET /featured`. | Одоо: идэвхтэй, зурагтай кафе, шууд хэмжилттэй нь эхэнд (`featuredCafes`, `home-data.js`). Төлбөртэй болоход «Сурталчилгаа» гэж шошголно (TODO тэнд). |
| 10 | **Жагсаалтад үнэлгээ:** `GET /cafes`-д `rating: { average, count }`. | Одоо нүүр нь харагдаж буй хүртэл 12 бодит кафены `GET /cafes/:id/ratings`-ийг тус тусад нь асууна. Сэтгэгдэлгүй бол од харагдахгүй. «Үнэлгээ» эрэмбэ зөвхөн үнэлгээ ирсэн үед гарна. |
| 11 | **Бодит координат:** `lat`, `lng` (одоо зөвхөн газрын зургийн `x`, `y`). | Зай нь хэрэглэгч «Ойролцоо» товч дарж байршлаа зөвшөөрсний дараа л, демо биш кафед тооцогдоно. Байршил сервер рүү явахгүй. «Ойрхон» ангилал, эрэмбэ зөвхөн тэр үед гарна. |
| 12 | **Тагууд:** «Залгууртай», «Хүүхдийн булан» зэрэг онцлогийг `tags`-д сонгох жагсаалтаар оруулах. | Ангилал тухайн таг бүхий кафе байхгүй бол нуугдана. |
| 13 | **Багц/төлөвлөгөө** (жишээ нь `plan: 'basic'`). | Загварт «Basic» гэж байсан ч API-д талбар байхгүй тул бичээгүй; шууд хэмжилтгүй кафе «Шууд хэмжилтгүй · цэс, сэтгэгдэлтэй» гэж харагдана. |
