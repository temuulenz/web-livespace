# Backend-to-frontend handoff

Reuse PHASE11_API_CONTRACT.md, FRONTEND_INTEGRATION_GUIDE.md and feature guides; OpenAPI/Postman updated for promotions/readiness. No frontend file was changed. Existing cookie login/registration, owner claim, tenant roles, public/private projections, pagination and realtime formats remain compatible for valid requests.

New behavior: mutation-time session/role/ownership changes return 409 access_changed; reload/re-authenticate before a new intentional mutation. Existing version/idempotency conflict handling remains required. Node rejects non-object JSON roots with400 and cross-scheme origins with403. Production proxy/HTTPS settings must match legitimate origin. Node errors supply X-Request-ID and sanitized unexpected-error logs; no credentials/bodies logged. GET /api/v1/ready is an operator DB/schema probe, never an indication full Phase11 or production readiness passed.

Promotion UI integration is optional teammate work: owner CRUD/publish/pause/archive and integer-MNT preview; public active list. Schedules use UTC envelopes/Asia-Ulaanbaatar recurrence; informational student/combo announcements never imply a calculated discount. No client prices accepted; overlap does not stack. See PROMOTION_ENGINE.md for exact requests/responses/errors/limits.

Discovery landing sections can use existing GET /api/v1/cafes and /live: currently-open uses returned open flag; quiet/noise and less-crowded sections must use fresh, valid, real compatible measurements and their source/unit labels. Observed people is not occupancy percentage or available seats. Never rank uncalibrated dBFS as SPL. Missing values are unknown, not quiet/empty. Map x/y are illustrative coordinates, not GPS distance. Nearby sections require actual suitable location data and location permission; if unavailable, offer unranked existing discovery or explicit user selection. Do not invent verified-distance/featured ranking APIs. Optional rotating sections are presentation owned by frontend, not implemented here. Empty results stay empty with freshness/source explanation; do not inject fake live data.

Recommended integration tests: guest cannot mutate/read private records; owner A cannot access B; revoked session during delayed mutation cannot commit; duplicate stock request gives no second movement; hidden menu/product/promotion references disappear; no-review averages are null; inventory delta omitted quantity removes old visible quantity; SSE/browser resync recovers gaps. Use synthetic local fixtures, never production credentials.
