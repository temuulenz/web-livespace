# Browser realtime and sensor compatibility

Current Phase 11: existing inventory/sensor SSE and cafe rooms are preserved. Persistent notifications use recipient-scoped HTTP inbox/read/preferences, never public SSE. Optional realtime notification delivery was not necessary or added. See NOTIFICATIONS.md; earlier absent business-event statements below are historical.

Current Phase 11 status (2026-11-17): inventory events/snapshot recovery are implemented as documented in INVENTORY_MANAGEMENT.md. Older statements below about absent business events are historical. Notification infrastructure in 11G remains incomplete.

`/ws/sensors` retains the frozen Android v1 JSON/auth/ACK/replay contract and existing SensorGateway class. Node SSE and bounded polling remain supported. The new `/ws/browser/:cafeId?scope=public|owner|admin` endpoint uses one SQLite BrowserRoom DO per stable `cafe:{id}`, not one per browser and not a global private room. Wrangler prepares the binding and additive DO class migration; no namespace exists remotely until an approved deployment. Browser realtime requires `LS_BROWSER_REALTIME_ENABLED=1` plus the binding.

Same-origin Origin is mandatory for browser upgrades; production uses HTTPS/WSS. Public subscribers require an active cafe. Private subscribers use existing HttpOnly sessions and D1 ownership/RBAC; bearer sensor tokens do not authenticate browsers. Session hashes, credentials and private diagnostics never appear in public frames. Subscription attachments preserve cafe, scope and session hash through hibernation. Room identity is stored and mismatched tenants are rejected. Connection cap: 600 per cafe; per-IP upgrade admission is bounded separately.

All sockets use `acceptWebSocket`, durable attachments, and automatic `ping`/`pong` responses. No per-connection permanent server timer or per-connection DO is used. A room persists a recoverable, versioned public projection and optional private diagnostics in one SQLite row; D1 history remains authoritative. Freshness derives from observation timestamps, never ping/pong. On a cold room, reconnect, or missed delivery, an authoritative D1-derived snapshot recovers state. Connection eligibility is checked before acceptance; concurrent snapshots share refresh work and public snapshots can reuse five-second room state.

After telemetry commit (or an authorized management mutation), trusted server RPC schedules a coalesced room refresh after 500 ms. Browser sockets cannot publish business mutations. One refresh projects a cafe once and fans out small typed `live.snapshot` frames with monotonic durable versions; individual public browsers cause no per-event database projection. Private session/ownership checks remain indexed and execute before every private broadcast. Private diagnostics are fetched only when private subscribers need them. Private and public frames are constructed separately.

Notification is best-effort and independent of durable acceptance. A lost RPC can delay updates until the room's next minute maintenance alarm or reconnect. The alarm also rechecks authorization/publication state, refreshes offline/stale projections, and sleeps when no sockets remain. Private revocations are enforced on the next notification/maintenance check (normally at most 60 seconds). A notification failure never changes a committed ACK and never causes acceptance of unpersisted telemetry.

The native browser manager keeps one connection per live cafe for the tab across hash navigation. Initial validated snapshots stop fallback polling only when all selected rooms are healthy. Reconnect uses exponential backoff/jitter, duplicate versions are ignored, wrong-cafe frames are rejected, and reconnect snapshots restore missed state. Hidden tabs close sockets and stop fallback activity; visible tabs reconnect. A 30-second client heartbeat is automatically answered without waking the DO. The client does not keep a server-side interval alive. Fallback preserves Node SSE or Cloudflare's existing quota-aware polling. Initial all-demo catalogues continue polling; cafe additions require catalogue refresh/reload, as in the existing catalogue workflow.

Quota failures send `service.unavailable`, close 1013, and apply a 15-minute room/client backoff. Existing client stale labels continue to expire old observations. Five-second cached public snapshots are recoverable derivatives, not new credentials or authoritative latest-state tables. Longer cadence requires matching stale thresholds.

Business events are reserved for future phases: persist the authoritative mutation, then notify, and recover through a fresh authorized snapshot. Delivery is not a write receipt. Phase 11 menu/inventory/order events are not implemented here.
