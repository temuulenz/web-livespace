# Phase 11A menu backend

Implemented in shared/business/menu.mjs and menu-media.mjs, with thin Node and Cloudflare adapters. No frontend changes. D1 migration 0009 and Node migration 5 are additive. Existing Phase 7.1/7.2 work is preserved. Stable IDs support future order references; no orders exist.

All owner routes start `/api/v1/owner/cafes/{cafe}/menu`. Existing cookie session is required; role owner or admin AND actual cafe owner_id equality. Administrative role alone does not grant menu ownership. Cross-tenant requests return 404. Writes require same-origin requests under existing session/CSRF policy. All routes are limited to 120 requests/minute per process/isolate and client IP (not a distributed abuse limit). JSON bodies are 16 KiB except image upload (1,450,000 bytes). Errors use existing `{error:{code,message}}` envelopes.

| Method | Suffix | Request | Success |
|---|---|---|---|
| GET | /categories, /products, /variants | query below | `{items:[],pagination:{limit,offset,has_more}}` |
| GET | /{collection}/{id} | none | `{item:{...}}` |
| POST | /{collection} | create fields below | 201 `{item:{...}}` |
| PATCH | /{collection}/{id} | changed fields plus current integer version | 200 `{item:{...}}` |
| DELETE | /categories/{id} | none | `{deleted:true}`; 409 while referenced |
| DELETE | /products/{id} | none | archived product object, stable ID retained |
| DELETE | /variants/{id} | none | inactive variant object, stable ID retained |
| POST | /{collection}/bulk | `{items:[{id,version,published:false}]}` | `{updated:1}` |
| POST | /import/preview | `{csv:"..."}` | `{preview_id,products:[],published:false,requires_confirmation:true}` |
| POST | /import/confirm | `{csv,preview_id,confirm:true}` | `{imported,duplicate}` |
| PUT | /products/{id}/image | `{version,image:"data:image/jpeg;base64,..."}` | `{item:{...}}` |
| DELETE | /products/{id}/image | `{version}` | `{item:{...}}` (detach; retain stored object) |
| GET | /products/{id}/image | optional If-None-Match | binary raster or 304 |

Category fields: required `name`; optional `description,display_order,published`. Product: required `category_id,name,base_price`; optional `description,discounted_price,featured,published,archived,display_order`. Variant: required `product_id,name,price`; optional `discounted_price,active,display_order`. Unknown JSON fields rejected. Defaults: draft category/product, active variant, display_order 0, empty description, no discount. Flags must be JSON booleans on input; database integer flags are returned as 0/1. IDs, cafe IDs, timestamps and image references are server controlled.

Names/references <=120 characters; descriptions <=2000. Prices are safe integer MNT 0–1,000,000,000, discounts null or 0–base price. Orders are nonnegative integers <=1,000,000,000. Category/product/variant references are tenant validated and reinforced by composite foreign keys. Product image_ref is a media ID; fetch image by the product image endpoint. Product and variant responses include version and UTC created_at/updated_at. PATCH requires current version; stale/concurrent updates produce 409 version_conflict. Atomic batches include an audit entry; failed version guards roll back the batch.

Owner list parameters: limit 1–100 (default 50), offset 0–10000 (default 0), q <=120 (literal substring), plus supported collection fields published/archived/featured/active as true/false, category_id or product_id. Sorting is display_order then ID. Bulk edits accept 1–10 distinct IDs and versioned patches, atomically; use display_order for reordering and published for publishing/hiding. Maximum 100 categories, 1000 products, 2000 variants per cafe, 20 variants per product for individual creation. Limits include archived/inactive records. CSV imports cap 20 products and enforce the product capacity. Database insert/update triggers also enforce the per-product variant cap during reassignment, including bulk edits. Aggregate cafe/media capacity checks still require concurrent-create hardening before rollout.

CSV header must be exactly `category_id,name,description,base_price,discounted_price`. Quoted commas, escaped quotes and CRLF supported. Maximum 12000 bytes, 1–20 rows. Preview validates every row and makes no changes. Confirm resends the identical CSV and its preview_id with explicit confirm:true; prices and tenant relationships are revalidated, all rows inserted as drafts in one transaction. Audit-backed confirmation receipts suppress sequential retries. Concurrent identical confirms may return a conflict/error; retry resolves against the durable receipt. IDs remain stable. No spreadsheet formula execution or frontend CSV handling is implemented.

Public contract: `GET /api/v1/cafes/{cafe}/menu`. This is the stable cafe-specific menu URL for future QR integration. Returns `{cafe_id,menu_url,categories:[],products:[{...product,variants:[]}],pagination}`. Only active cafes, published categories, published nonarchived products, active variants. Use `product_id` for details, `category_id`, `featured=true|false`, q, limit, offset for filtering. Categories contain at most the tenant category cap (100). Products without variants return variants:[]. Images: `GET /api/v1/cafes/{cafe}/menu/products/{product}/image`; publication and cafe status are rechecked before returning bytes. Public inventory is now available separately; see INVENTORY_MANAGEMENT.md. Menu snapshots intentionally remain independent of stock.

All API JSON is no-store. Server-side snapshots have a five-second TTL, 128-entry bound, tenant+query keys, and targeted post-persistence mutation invalidation. Cafe visibility is checked even on cache hits. Menu writes do not evict homepage/profile caches. No homepage menu loading or N+1 variant queries. Node cache lives with its app; Cloudflare cache is isolate-local and optional on binding reuse. Never use this cache as authoritative storage.

Media reuses shared Phase 7.2 structural raster validation, Node uploads, and Cloudflare mediaKey/mediaResponse. JPEG, PNG, WebP only; maximum 1 MiB, existing dimension checks; no SVG/HTML. Node uses tenant-scoped files, Cloudflare optional R2 (no resources created), otherwise D1 bytes. Durable intent precedes object/file writes; publication reference updates and audit commit atomically after storage. Images deduplicate within each cafe by SHA-256. Old images remain recoverable after replacement and never delete a possibly referenced object. Per-cafe limits: 100 retained images / 20 MiB; global 50 MiB application cap. Headers use ETag, nosniff and conservative private revalidation even for public images. Atomic quota reservations and bounded physical orphan reconciliation are implemented by the hardening described below. Failed pending uploads require operator reconciliation before identical-image retry. No unreferenced object is deleted automatically by a request failure.

Errors: 400 malformed JSON, 401 unauthenticated/revoked, 403 role/origin, 404 absent/cross-tenant/hidden, 409 version_conflict/category_in_use/menu_limit/media_budget/media_pending/preview_mismatch, 413 body limit, 415 content type, 422 validation_failed/invalid_csv/invalid_image, 429 rate_limited, 503 unavailable storage. Unexpected storage failure never reports a successful mutation. Sensitive SQL/storage diagnostics stay off the public response.

Tests cover service CRUD, foreign tenants, malformed prices, discounts, publication, soft deletion, version conflicts, atomic bulk validation rollback, CSV preview/confirmation/retry, schema parity, HTTP owner/guest/CSRF and media visibility/ETag. Cloudflare local workerd checks D1 CRUD/bulk/media fallback. Optional local R2 failure/recovery tests now pass; full mixed release workload measurements remain outstanding. No realtime menu event is emitted by 11A; clients refresh the menu after their own edits. Inventory deltas belong to 11B.

## Completed hardening (current; supersedes checkpoint limitations above)

11A is complete for local backend integration. Additive Node migration 6 / D1 0010 adds transaction-maintained tenant counters (100 categories, 1000 products, 2000 variants, 100 images/20 MiB) and a global 1000-image/50 MiB reservation counter. CHECK constraints enforce admission inside each insert transaction, including concurrent creates and CSV imports; rollback also rolls back counters. Pending images reserve capacity. Migration seeds counters from existing records and safely aborts if prior data exceeds configured bounds; it never deletes excess data. Tenant/image-size mutations are fenced. Per-product variant cap remains enforced on insert/reassignment.

Upload intent now records the planned file/R2 key before byte writes. Ready media and product references are checked by database triggers, preventing cross-tenant or retired references even during concurrent cleanup. D1 remains authoritative. `reconcileMenuMedia` in shared/business/menu-media-reconcile.mjs is a trusted operator utility, not an HTTP deletion endpoint. It requires cafe_id, cutoff at least 24 hours old, defaults to dry_run:true, and handles at most 20 images plus 20 cleanup records per pass. It atomically journals and removes only unreferenced metadata before physical deletion, retains tombstones after failures/ambiguous writes, and rechecks references. Late upload completion cannot reattach a retired ID; tombstones allow repeated physical deletion following a crash. Failed identical uploads can be retried after reconciliation. Referenced images, including archived products' references, are protected. Old pre-hardening pending entries without locators require operator inspection; never guess deletion paths. Cleanup records are capped at 1000 globally; reaching the cap explicitly refuses further retirement. Pruning tombstones requires a separately reviewed, quiescent operator procedure; no automatic destructive pruning occurs.

Public categories and product details deliberately use the existing snapshot (`category_id`, `product_id`, `featured`) contract; no duplicate API or QR UI is needed. A 100-product page can include at most 2000 active variants and 100 categories; variants use two bound parameters with json_each rather than exceeding D1's parameter ceiling. Maximum-tenant tests keep snapshot JSON under 1 MiB for representative bounded fields; response size can be larger with maximum-length descriptions, and the configured entity/page limits remain authoritative. Use smaller pages on constrained clients.

Tests: 122 Node, 26 focused sensors, 24 local Cloudflare checks and Wrangler dry-run pass. Four new hardening tests cover atomic quota races/rollback, byte reservations, failed storage/reconstructed service/GC authorization, and maximum snapshot/publication checks. `scripts/phase11-d1-check.mjs` exercises the actual local D1/R2 adapters, version races, injected post-write rollback, ambiguous R2 writes, recovery with a new service instance, tenant denial and indexed plans. Local D1 metadata: product create 4 reads/9 writes; product edit 5/4; cold 30-product snapshot 95/0; warm 1/0; R2 upload/attach 10/15. See PHASE11_MENU_D1_MEASUREMENTS.json. These include index/trigger work exposed by local workerd, not production billing or internet latency. Full mixed Phase 11 capacity scenarios remain a release-level task after later subphases exist. No sensor ingestion architecture changed.
