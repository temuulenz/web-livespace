# Optional media storage

D1 owns application/photo metadata and permissions. Node keeps its filesystem adapter. Cloudflare defaults to existing `photo_bytes`; R2 new writes require both `LS_R2_MEDIA_ENABLED=1` and a private `MEDIA` R2 binding. No binding is created by this repository. Public R2 endpoints/custom domains must stay disabled. Existing `/api/v1/files/photos/:id` URLs always authorize against D1 before opening an object or returning 304. Application photos remain private even if a future generic media pointer is marked public. There is no HTTP delete or generic upload endpoint.

New object keys are `media/v1/cafes/{cafeId}/{photoId}.{ext}`. Version and tenant identity are explicit; object names are generated, never supplied paths. The D1 metadata pointer is committed with application records only after R2 put succeeds. New R2 photos have no D1 blob. Optional public response support in the adapter is for future explicitly public media, not automatic publication of onboarding photos.

JPEG/PNG/WebP bytes undergo bounded structural/header/dimension checks, canonical base64 and actual-byte size checks; SVG, animated WebP, MIME spoofing, truncated structures and trailing content are rejected. This parser is not a full pixel decoder or malware scanner. Browser rendering uses nosniff, raster MIME, sandbox CSP, and no script context. Images are compressed to WebP in the browser with a 300 KiB target and 1 MiB hard Cloudflare upload cap, 1600-pixel longest edge. Unsupported WebP export uses the browser's raster fallback. No paid image transforms run inside Workers. Existing dashboard photos already lazy-load.

R2 bodies stream through the authenticated route; D1 legacy blobs necessarily materialize. ETags and If-None-Match support conditional responses. Private responses use `private, no-cache` and Vary Cookie so revocation is checked on each retrieval. A future public media route may use the adapter's public cache policy only after explicit publication checks.

D1 and R2 cannot share a transaction. The `media_staging` journal is written before object upload and retained on failure/ambiguous commit. A failed request never deletes an object that might already be referenced. `reconcileMedia` is an operator-only, cafe-scoped, dry-run-by-default reconciliation for journals older than 24 hours. It checks authoritative references before deleting an unreferenced object; never run it against in-flight uploads. Referenced entries only clear the journal. A complete platform outage can delay reconciliation; temporary staged objects are a known bounded orphan window, not a false atomicity guarantee.

Initial application budgets: 1,000 referenced plus journaled objects, 512 MiB aggregate referenced/journaled bytes, 1 MiB/image, 3–4/application, existing five applications/IP/hour limiter. Counts are small metadata scans in the existing API DO, not bucket listings. These are conservative application admission limits, not billing caps; distributed abuse, account-level usage, failed operations and untracked external objects can still incur charges. Do not enable R2 billing or a plan without explicit approval.

## Existing photo copy and rollback

`scripts/media-migrate.mjs --local` plans up to 1,000 existing local photos; `--local --apply` copies, hashes the actual uploaded bytes, and atomically attaches metadata, retaining every original D1 blob. `--local --verify` checks existing copies without writing. Repeated runs skip/verify attached pointers. Invalid legacy images are reported and preserved, never deleted. Migrate local D1 schema first. The utility deliberately has no remote mode. Production use needs separately reviewed operator tooling and approval; do not point the local utility at a remote resource.

Rollback plan: disable new R2 writes, retain the binding for reads of R2-only photos, and keep additive schema. For copied legacy photos, removing only reviewed metadata pointers restores their unchanged D1 bytes. Never remove R2 bindings while R2-only media exists; never delete original blobs or objects as an automatic rollback. Inventory and reconcile staged copies before any approved production migration.
