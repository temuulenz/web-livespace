# Phase 11G in-app notification backend

Transactional outbox triggers enqueue alongside review/reply/moderation, stock, promotion and sensor mutations on both SQLite/D1. Trigger failure rolls back the domain write; no successful receipt is issued for a failed transaction. Outbox and inbox survive restarts. No external email/SMS/push provider exists; none was added. External failures are zero with explicit not_configured status, not invented provider delivery metrics.

GET `/api/v1/me/notifications?limit=1..100&offset=0..10000` → `{items:[{id,cafe_id,category,entity_id,severity,created_at,read_at}],pagination,unread}`. POST `/api/v1/me/notifications/{id}/read` and `/api/v1/me/notifications/read-all` → `{read:true}`. GET/PATCH `/api/v1/me/notification-preferences` → `{preferences:{category:boolean,...}}`; PATCH is a partial category-to-boolean map, rejecting unknown keys. Existing authenticated sessions/same-origin policy required; per-runtime 60 requests/IP/minute plus existing API admission. A foreign notification returns 404. No endpoint accepts a recipient ID.

Categories/defaults: review_submitted, review_reply, inventory, promotion_expiry, sensor_offline, sensor_recovered, resource, moderation default on; promotion defaults off. Promotion recipients must both explicitly opt in AND currently favorite the cafe; only active cafes and published, scheduled/current promotions qualify. Operational categories remain distinct from marketing. Resource severities are warning/critical/hard_limit; other events default info. Display strings are frontend-owned; the API carries bounded category/entity references without review text, account details, tokens or private diagnostics.

Triggers: new review→current owner; owner reply/edit→review author; moderation→author and owner; low threshold crossing or sold-out transition→owner; promotion publication (scheduled at start if future)→eligible opted-in users; approaching expiry→owner (default 24 hours); real enabled sensor offline/recovered→owner and current enabled admins; quota warning/critical/hard transition→admins only. A first connection without an offline incident is not recovery. Repeated same status does not create another incident; source IDs/versions and durable delivery receipts deduplicate repeated processing. Simulation never generates real sensor incident alerts. Reminder candidates also cover previously published promotions.

Worker resolves current recipients and rechecks identity/preferences/owner or administrator eligibility within the insert. No arbitrary recipient selection. One recipient/event page per maintenance call bounds D1 queries; backlog is durable and event-driven alarms drain it. Node runs maintenance every 30 seconds. Cloudflare starts a near-term alarm after mutations, then follows pending outbox due times, otherwise performs a 15-minute sweep. Heartbeat/gateway status changes remain authoritative; sweep uses the configured telemetry offline threshold even with open transport. No new sensor protocol or credential store.

Default cooldown one hour/category/entity, configurable. Stock threshold crossings have distinct incident/version keys; resource severities have separate cooldown keys so critical escalation is not hidden by a warning. Notification budget defaults 100 new inbox rows/recipient/UTC day, atomically admitted. Over-budget work is deferred one hour, not deleted. Opt-outs/cooldown suppression are recorded durably; duplicate work cannot increment budgets again. Multiple concurrent workers share atomic inbox, cooldown and budget guards. External retry statuses are unnecessary without external delivery; outbox attempts represent in-app processing, never an email receipt.

Default inbox/processed-outbox retention 90 days in bounded batches; retained delivery receipts preserve deduplication for accepted domain events. No customer content is deleted. Operators can POST `/api/v1/admin/maintenance` to execute one bounded maintenance step, admin only. Queues may take multiple steps; this endpoint does not mean the whole backlog is empty. No public notification SSE channel was added, so private frames cannot accidentally enter the existing public SSE stream.

Tests: phase11-notifications.test.mjs and phase11-resources.test.mjs cover domain triggers, targeting, marketing consent, read isolation, repeated sensor incidents, reconstructed service, quotas and admin threshold events; local Cloudflare integrated checks exercise persistent outbox/inbox/preference/read APIs.
